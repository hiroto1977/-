# 事業継続 —— 他社のクラウドが止まったとき

2026-11-11。台帳は `src/shared/cloudContinuity.ts`、画面は設定画面の「事業継続」の節
(`src/renderer/components/CloudContinuityPanel.tsx`) と「暗号化した控え」の節 (`EncryptedCopyPanel.tsx`)。

## 1. 立て付け

- **事業の記録の正本は端末に在る。** 売上・KPI・貸借対照表・書類・水耕栽培の記録などは端末の中 (IndexedDB) に
  保存する。どのクラウドが止まっても読み書きできる。
- **端末の故障にはクラウドで備える。** 暗号化した控えを、クラウドと同期しているフォルダへ書く (§4.1)。
  提供者が持つのは暗号文だけ。
- **クラウドは 2 通りに使う。** 提供者が預かるデータを見せる先 (GitHub・Google・freee など) と、
  一部の操作を助ける先 (AI の応答・漏洩の照会・連携先への通知)。
- **どの画面がどちらに当たるかは手で書かない。** 既に在る 2 つの宣言から導く。

| 立ち位置 | 導き方 | 止まったとき |
| --- | --- | --- |
| この端末だけで動く | 下の 2 つのどちらでもない | 何も変わらない |
| 端末で動き、一部の操作だけクラウドを使う | 端末の外へ出る action (`ACTION_TIER` の `external-write` / `egress`) を持つ | その操作だけが失敗して理由を表示する。画面と計算は動く |
| クラウドが預かるデータを見る | 出どころ (`SERVICE_DATA_ORIGIN`) が `remote` | 取得が失敗してエラーを表示する。アプリを開いている間は、最後に取得できた内容を時刻つきで見せ続ける (§4) |

件数は設定画面の節が `continuityTotals()` から刷る (ここには書き写さない)。

例外は 1 つ: Ollama は端末の外へ出る action を持つが、相手は利用者自身の Ollama (既定は同じ端末) なので
「他社のクラウド」に数えない (`OUTBOUND_NOT_THIRD_PARTY`・理由つき・両方向)。

## 2. 提供者の台帳

`CLOUD_PROVIDERS` が提供者ごとに 1 行を持つ: 何を預けているか・止まったらこのアプリで何が起きるか・
その間どう続けるか。行の種類は 3 つ。

- `data` —— 預かるデータを見せる提供者。
- `assist` —— 記録は預けず、操作のたびに必要な物だけを送る相手 (AI・漏洩の照会・連携先への通知)。
- `infrastructure` —— 画面に結び付かない依存先 (公開サイトの置き場・利用者が建てたプロキシ・更新の確認)。
  行は実物のファイルを指す (`evidence`)。

設定画面の節は、**いま資格情報を預けている提供者だけ**を台帳の順に並べる (`outageExposure`)。
資格情報の一覧を読めなかったときは「預けていない」と言わず、確かめられないと言う。

## 3. 実測

- **取得の演習 (両ビルド)。** 「預かるデータを見る」以外のすべてのサービスについて、実物の取得を
  網が止まった状態で呼ぶ。端末の外へ向いた呼び出しは 0 回で、取得は失敗しない (見本か端末の記録を返す)。
  デスクトップ版は `src/main/clients/__tests__/cloudOutageDrill.test.ts`、
  ブラウザ版は `src/renderer/__tests__/cloudOutageDrillWeb.test.ts`。
  ブラウザ版は全サービスに資格情報を預けた状態で測る (預けていても外へ出ないこと)。
- **対照。** 「預かるデータを見る」サービスは実際に外へ出ようとして失敗する (数え方が空でない証拠)。
- **取得が失敗した画面。** `useServiceData` はエラーを表示し、最後に取得できた内容が在ればそれを時刻つきで見せる (§4)。

## 4. クラウドを使って穴を塞ぐ 2 つの口

### 4.1 暗号化した控え —— 端末の故障に備える (クラウドには暗号文だけ)

穴: 正本が端末に在るので、端末が壊れると事業の記録を失う。控えは手で書き出すしか無く、古くなっても誰も言わなかった。

設定画面の「暗号化した控え」(`renderer/components/EncryptedCopyPanel.tsx`・判断は `renderer/data/encryptedCopy.ts`):

- 端末の記録をパスフレーズで暗号化して、**保存先フォルダ** (設定画面の「PC のフォルダに同期」で選ぶ) へ書く。
  そのフォルダをクラウドと同期しているフォルダにすれば、**提供者が持つのは暗号文だけ**になる。
- **パスフレーズは保存しない。** 書くたびに 2 つの欄へ打つ (一致しなければ書かない —— 打ち間違えた控えは開けない)。
- **書いた物を読み戻し、そのパスフレーズで開けて件数が合うことを確かめてから「書けた」と言う。**
- ファイル名は日付ごとに 1 つ (`service-hub-copy-YYYY-MM-DD-encrypted.json`)。同じ日は上書き、別の日は世代として残る。
  空の控えは書かない (同じ日の控えを空で上書きしないため)。
- **鮮度を言う。** 端末は目印 (書いた時刻・件数・記録の指紋・ファイル名) を覚え、記録が変わったら
  「最後の控えのあとに記録が変わっています」と警告する。目印に記録の中身もパスフレーズも入らない。
- 戻すときは「バックアップ / 復元」に、その控えのファイルとパスフレーズを指定する (形式は同じ 1 つ)。

### 4.2 最後に取得できた内容 —— クラウドが止まっている間も見える

穴: 預かるデータを見る画面は、取得が失敗したあとに開き直すと同梱の見本に戻っていた。止まっている間こそ
「最後に見えていた姿」が要る。

`renderer/data/lastGoodFetch.ts` が、クラウドから取得できた内容を**メモリにだけ**覚える。次の取得が失敗したら、
失敗の文に「最後に取得できた内容 (月/日 時:分 時点) を表示しています」と足してそれを見せる。

- **端末には保存しない** (再読込・アプリの終了で消える)。持つ物を増やさないため。
- 覚えるのは出どころが `remote` の内容だけ。見本を名乗る内容 (`isMock`) は覚えない。
- **施錠したら全部消す。** 資格情報が無いと断られたら、そのサービスの分を消す。

## 5. 責任の所在

**ソフトウェアは、賠償や訴訟の責任を提供者へ移せない。** どこまでを提供者が負うかは、各社との契約と法律で決まる。

- 一般的なクラウドの利用規約は、提供者の責任に上限を置く (多くは支払った利用料の範囲)。
  間接損害・逸失利益は除かれることが多い。無料プランには稼働率の約束が無いことが多い。
- 預けたデータの中身・共有の設定・アカウントの管理は、預けた側の持ち分である。
- 個人データの取扱いを委託するなら、委託先の監督は委託元の義務である (個人情報保護法 25 条)。
  委託先で漏えいが起きたときの報告も、原則として委託元が負う。
- 税の申告・書面の記載・取引先との契約の当事者は自社のままである。

このアプリにできるのは、**持つ物を減らす・送る物を絞る・依存と持ち分を見えるようにする**ことまで。
台帳と画面は `LIABILITY_NOTE` と `RESPONSIBILITY_STAYS` でそれを述べる。法的な助言ではない。

### 提供者ごとに確かめる契約の項目

1. 稼働率の約束と、割ったときの補償 (返金の上限)。
2. 責任の上限と、除かれる損害。
3. 第三者からの請求に対する補償 (知的財産・データの漏えい) の有無と条件。
4. データ処理の契約 (委託の範囲・再委託・漏えい時の通知の期限・保管する国)。
5. 準拠法と管轄。
6. 解約・停止のときのデータの書き出しと、消去までの期間。

残る危険は、契約の交渉・保険 (サイバー保険・賠償責任保険)・弁護士の確認で埋める物である。

## 7. 限界と、次の候補

- **最後に取得できた内容は、再読込すると消える。** メモリだけの覚えなので、止まっている間にアプリを開き直すと
  同梱の見本に戻る。端末に残す形は候補だが、持つ物が増える (端末の側の漏えいの危険・消す口・バックアップの範囲)。
- **暗号化した控えは、書くたびにパスフレーズを打つ。** 自動では書かない (パスフレーズを保存しないため)。
  画面は控えが古いことを警告するが、設定画面を開かなければ見えない。
- **保存先フォルダを同期するのは OS の側のクライアント。** フォルダがクラウドと同期されているかを、アプリは確かめられない。
- **パスフレーズを忘れると控えは開けない。** 復旧の手段は無い。
- **演習が測るのは取得まで。** 操作 (action) がクラウドの停止でどう失敗するかは、個々の検査が見る。
- **端末そのものの故障**は別の話で、控え (バックアップ) が受け持つ。
