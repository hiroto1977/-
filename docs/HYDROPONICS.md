# 水耕栽培 — 集める情報と自動管理の仕様

> 2026-09-13 (パス 194) 新設。実装は `src/shared/hydroponicsControl.ts` (判定)・
> `src/renderer/data/hydroponicsLog.ts` (保存)・`src/renderer/pages/HydroponicsPage.tsx` (画面)。
> 既に在る**試算**の層 (`hydroponics.ts` / `waterCyclePlanner.ts` / `hydroponicCrops.ts`) は
> このファイルの §7 で対比する。

## 0. この仕様が答える問い

**「今日、この栽培室で何をすればよいか」** を、毎日の測定から自動で出す。

```
  毎日の測定  ──┐
  栽培ロット  ──┼─→ 判定 ──→ 今日やること (期限つき・重さつき・調製量つき)
  運転の設定  ──┘
```

答えないことも先に書く: **収量と損益の試算**は別の層 (§7)、**装置の自動制御**は
行わない (この仕様は人が動くための指示を出すところまで)。

## 1. 集める情報

### 1.1 毎日測る 8 項目

| 項目 | 単位 | 妥当範囲 | 目標域の出所 | 効く側 |
| --- | --- | --- | --- | --- |
| 養液 EC | mS/cm | 0〜10 | **品目ごと** | 下限・上限 |
| 養液 pH | — | 0〜14 | **品目ごと** | 下限・上限 |
| 養液温度 | ℃ | −5〜60 | 栽培室ごと | 下限・上限 |
| 室温 | ℃ | −20〜60 | 栽培室ごと | 下限・上限 |
| 相対湿度 | % | 0〜100 | 栽培室ごと | 下限・上限 |
| CO₂ 濃度 | ppm | 0〜50,000 | 栽培室ごと | 下限・上限 |
| 溶存酸素 | mg/L | 0〜25 | 栽培室ごと | **下限だけ** |
| 養液タンク液位 | % | 0〜100 | 栽培室ごと | **下限だけ** |

- **「妥当範囲」は桁誤りと測定器の異常を止める幅**であって、栽培上の適正域ではない
  (`HYDROPONIC_CROP_BOUNDS` と同じ役目・同じ言い方)。外に出た値は「読めない」。
- **下限だけが効く 2 項目**は「高すぎ」を咎めない —— 溶存酸素が高いのは曝気が効いて
  いるだけ、液位が満水なのは問題がない。
- 一覧は `READING_FIELDS` が唯一の出所。画面の入力欄・判定・作業リスト・fetcher の
  台帳がすべてここから導かれる (数を 2 か所に書くと必ず食い違う)。

### 1.2 栽培ロット

| 欄 | 意味 |
| --- | --- |
| ロット名 | 一覧と作業リストに出る名前 (40 字まで) |
| 品目 | `hydroponicCrops.ts` の一覧から選ぶ (利用者が足した品目も可) |
| 播種日 | `YYYY-MM-DD`。**暦に在る日だけ** |
| パネル枚数 | 1 以上の整数 |
| 状態 | 育苗中 / 定植済み / 収穫済み / 廃棄 |
| 定植日・収穫日・養液交換日 | **未定なら空欄 (`null`)**。入れたら暦を検査する |

### 1.3 運転の設定

**目標域 (10)** 養液温度・室温・相対湿度・CO₂ の下限/上限、溶存酸素の下限、液位の下限。

**調製の設備 (5)**

| 欄 | なぜ要るか |
| --- | --- |
| 養液タンクの容量 (L) | 足す量は容量に比例する。無ければ量を出さない |
| 原液の EC 上昇率 (mS/cm per mL/L) | **製品ごとに違う**。水 1 L に原液 1 mL で EC がどれだけ上がるかを実測して入れる |
| 原水のアルカリ度 (mg-CaCO₃/L) | 酸の当量がこれで決まる。無ければ酸の量を出さない |
| 酸の規定度 (N) | 同上 |
| 残すアルカリ度 (mg-CaCO₃/L) | 全部中和すると pH が振れやすい。既定 30 |

**運転 (3)** 養液交換の周期 (既定 14 日)・記録の途絶と見なす日数 (既定 3 日)・
収穫の予告日数 (既定 3 日)。

**低カリウム栽培の 2 欄は `hydroponics-setup` (試算側) から来る** —— 同じ値を 2 か所に
置かない。

## 2. 根拠の強さ —— どこまでが裏付けのある値か

**目標域の初期値はすべて `'reference'` (実務で広く使われる幅を置いた目安) で、
出典に当たって検証した値ではない。** `hydroponics.ts` の品目表が「リーフレタスだけが
出典で裏付けた値。他の 4 品目は相対で置いた目安」と書いているのと同じ姿勢である。

| 値 | 初期値 | 根拠 |
| --- | --- | --- |
| 養液温度 | 18〜22℃ | 目安。高いと根圏の溶存酸素が落ち、低いと吸水が鈍る |
| 室温 | 18〜25℃ | 目安 (葉物の生育適温帯) |
| 相対湿度 | 60〜80% | 目安。低いと蒸散過剰、高いと病害と葉先枯れ |
| CO₂ | 400〜1,500 ppm | 目安。外気は約 420 ppm。施用なら 800〜1,200 ppm を狙い、上限は**施用の行き過ぎを咎める**ため |
| 溶存酸素 | 5 mg/L 以上 | 目安 |
| 液位 | 60% 以上 | 目安 (補水の合図) |
| 養液交換の周期 | 14 日 | 目安 |
| アルカリ度 1 当量 | 50.04 mg-CaCO₃ | **化学量論** (CaCO₃ 100.09 ÷ 2) |
| EC の希釈 | 体積に反比例 | **物理** (溶けている量は変わらない) |

画面は項目ごとに「目安 / 出典あり」を刷り、冒頭に
**「自分の実測に置き換えて使ってください」** を常設する。`TARGET_BASIS` が
その印の唯一の出所で、検査が「今日はすべて目安」であることを総当たりで留めている。

## 3. 判定 —— 5 つの状態

```
  ok          目標域の中 (両端を含む)
  low / high  目標域の外
  unmeasured  測っていない (空欄)     ← ok ではない
  unreadable  読めない (妥当範囲の外・NaN・±Infinity・数でない値)
```

**守る規律**

1. **測っていない値を 0 に倒さない。** 「未測定」と「0 を測った」は打ち手が違う
   (前者は測りに行く・後者は調製する)。
2. **`allOk` は全項目を測ったうえで全部範囲内のときだけ true。** 1 つでも未測定なら
   false —— 測っていない物を「正常」と言わない。画面も未測定に色を付けない
   (緑でも赤でもない = 判定していない)。
3. **「測っていない」と「読めない」も混ぜない。** 読めない値は**刷らない** (pH 99 を
   「高すぎ」と言わず「読めません」と言い、測定器の校正を促す)。
4. **未測定の項目は作業リストに必ず出る** (`info`)。画面から消えると、緑の画面が
   「全部正常」に見えてしまう。

## 4. 調製 —— 出せる量と、出せない量

| 状況 | 出す物 |
| --- | --- |
| EC が低い | **原液 mL** = (目標 EC − 現在 EC) ÷ 上昇率 × タンク容量 |
| EC が高い | **足す水 L** = タンク容量 × (現在 EC ÷ 目標 EC − 1) |
| 液位が低い | **補水 L** = タンク容量 × (100 − 液位) ÷ 100 |
| pH が外れた | **アルカリ度を中和する酸の当量** (下記) |
| 温度・湿度・CO₂・溶存酸素 | **量は出さない** (空調・曝気の操作で、入れる量では直らない) |

目標 EC は**品目の適正域の中央**。狙う所を 1 か所で決める (`targetEcFor`)。

### 4.1 pH は「目標 pH までの酸の量」を出さない

必要量は水のアルカリ度と緩衝曲線で決まり、**水量だけからは決まらない**。
推定値で「この量を入れてください」と言うのは養液を壊す指示になる。

出すのは化学量論で決まる当量だけ:

```
  抜くアルカリ度 (mg/L) = 原水のアルカリ度 − 残すアルカリ度
  必要な H⁺ (meq)      = 抜くアルカリ度 ÷ 50.04 × タンク容量 (L)
  酸の量 (mL)          = 必要な H⁺ (meq) ÷ 規定度 (1 N = 1 meq/mL)
```

文には必ず **「目標 pH までの量ではありません —— 少量ずつ加えて pH を測り直して
ください」** を添える。

### 4.2 量を出せないときに何を出すか

```ts
{ kind: 'cannot', missing: ['養液タンクの容量 (L)', '原液の EC 上昇率'], how: '…埋め方…' }
```

**足りない物の名前と、埋め方**を返す。画面は作業行にそれを刷る ——
作業そのものは消さない (「EC を上げる」必要は変わらないから)。

## 5. 工程の日程

```
  定植予定日 = 播種日 + 育苗日数 (品目)
  収穫予定日 = (実際に定植した日 ?? 定植予定日) + 定植後日数 (品目)
  次の養液交換 = (最後の交換日 ?? 播種日) + 交換周期
  K 抜き切替日 = 収穫予定日 − 切替日数 (低カリウム栽培のとき)
```

- **実際の定植日が在れば収穫日はそこから数える。** 予定どおりに定植できなかった
  ロットの収穫日を予定のままにすると嘘になる。画面は「(実績起算)」と印を出す。
- **起点が無いときは 0 に倒さず播種日から数える** —— 「交換の記録がまだない」を
  「今日交換すべき」に化けさせない (理由も文で言う)。
- **K 抜き切替日は今日まで誰も出していなかった。** `assessLowPotassium` は切替日数が
  適正域 (7〜10 日) かを見るだけで、いつ切り替えるかは出していなかった (パス 67 は
  範囲判定だけを直した)。

## 6. 今日やること —— 重さの決め方

| 重さ | いつ | 例 |
| --- | --- | --- |
| `alert` 要対応 | 今日すでに害が出ている / 出荷物に影響する | 範囲外の項目・収穫遅れ・記録の途絶・K 抜き切替の遅れ |
| `warn` 今日 | 今日やるべき | 定植・養液交換・今日の測定がまだ・読めない値の測り直し |
| `info` 確認 | 近づいている / 測っていない項目が在る | 収穫が近い・未測定の項目 |

出る条件:

- 測定の記録が 1 件も無い → 「測定を記録する」(`warn`)。画面は
  **「全部正常ではなく、まだ分からない」**と明示する。
- 最後の測定から `readingStaleDays` 以上空いた → `alert` (この間の状態は分からない)。
- 直近の測定の範囲外 → `alert` + 調製 / 未測定 → `info` / 読めない → `warn`。
- 育苗中で定植予定日を過ぎた → 「定植する」。**収穫の作業は「定植済み」のロットに
  しか出ない** (工程を飛ばさない)。
- 定植済みで収穫予定日を過ぎた → `alert`。予告日数以内 → `info`。
- 養液交換の周期を過ぎた → `warn`。
- 品目が一覧から消えたロット → 「品目が見つかりません」(黙って落とさない)。
- **今日の日付が読めなければ作業を 1 件も出さない** (誤った期限を作らない)。

## 7. 既に在る層との違い

| ファイル | 答える問い |
| --- | --- |
| `hydroponics.ts` | **どれだけ採れて、いくらになるか** (設備 → 生産量 → 損益・低カリウム評価) |
| `waterCyclePlanner.ts` | **水と排水をどう回すか** (水収支・RO・硝化・曝気・排水基準) |
| `hydroponicCrops.ts` | **何を育てるか** (品目の一覧と栽培条件の編集) |
| **`hydroponicsControl.ts`** | **今日、何をするか** (測定 → 判定 → 作業) |

試算の層は「事業として成り立つか」を見る (経営サマリーの「水耕栽培の試算」)。
運転管理は**動いている栽培室を毎日回す**ための層で、入力は毎日変わる実測値である。

## 8. 保存する場所

| collection | 1 レコード | 選び方 |
| --- | --- | --- |
| `hydroponics-readings` | 測定 1 回 | 履歴として全件読む (日付の新しい順) |
| `hydroponics-batches` | 栽培ロット 1 つ | 全件 (播種日の新しい順) |
| `hydroponics-control` | 運転の設定 | **最新の 1 件を採用** |

- すべて **renderer の record store (端末内)**。主プロセスからは読めないので
  fetcher は利用者のデータを返さない (返すのは §1.1 の台帳)。
- 3 つとも `collectionShapes.ts` に登録済み —— 復元 (バックアップの取り込み) が
  形を検証する。**未入力を `null` で書く欄は `orNull(...)`** で受ける
  (`null` を落とすとその控えごと消える)。
- **読めない控えは件数として返し、黙って空にしない。** 画面が
  「N 件は読めませんでした」と言う。
- 個人情報の欄 (メール・電話・住所・代表者) は持たない → 平文バックアップの
  警告対象には入らない。ハードリセット (すべてのデータを削除) は record store 全体を
  消すので 3 つとも対象。

## 9. 入力の受け方 (書く側の規則)

| 入力 | 規則 |
| --- | --- |
| 空欄の測定値 | `null` (未測定) にする。**0 にしない** |
| 数でない測定値 | **断る** (黙って落とさない) |
| 妥当範囲の外 | **保存する前に断る** (測定器の校正を促す) |
| 1 項目も測っていない記録 | 断る (空の行を作らない) |
| 読めない日付 | **断る** (今日に倒さない) |
| 日付の前後が逆 | 断る (播種より前の定植・収穫は無い) |
| 同じロット名 | 断る (重複を黙って作らない) |
| メモの天井超え | **切らずに断る** (業務メモと同じ 2,000 字) |
| 設備の欄に 0 / 負 | 断る (0 除算と符号の逆転を作らない) |
| 目標域の下限 > 上限 | 断る (全項目が範囲外になる) |

## 10. 今は無いこと (正直に)

- **装置の自動制御はしない。** 出すのは人が動くための指示まで。ポンプ・電磁弁・
  空調への出力は持たない (持つなら安全側の停止条件から設計する)。
- **センサからの自動取り込みは無い。** 測定値は人が入れる。IoT からの投入を
  繋ぐなら、この仕様の `parseReading` を通す (妥当範囲の検査を迂回させない)。
- **目標域は出典で検証していない** (§2)。品目・季節・光量で動くので、自分の実測に
  置き換える前提である。
- **pH の目標値までの酸量は出せない** (§4.1)。アルカリ度の中和当量までが出せる限界。
- **収量の予測はしない。** 「収穫予定日」は品目の日数から数えた日付であって、
  実際の生育を見た予測ではない。
- 養液の**個別成分** (N / P / K / Ca / Mg / 微量要素) は測定項目に入れていない ——
  EC は総イオン濃度しか表さないので、成分の偏りは EC では見えない。実測できる
  事業者向けに項目を足すのが次の拡張である (低カリウム栽培の評価は既に
  **実測値しか受け取らない**形になっている)。

## 11. 検査の置き場所

| 何を | どこで |
| --- | --- |
| 判定・調製・日程・作業リスト (純粋関数) | `src/shared/__tests__/hydroponicsControl.test.ts` |
| 保存の読み書き・形の検証 | `src/renderer/data/__tests__/hydroponicsLog.test.ts` |
| 書いた物が復元の形を通る (往復) | `src/renderer/data/__tests__/collectionShapesRoundTrip.test.ts` |
| 台帳が shared の 1 か所から来る・通信しない | `src/main/clients/__tests__/hydroponics.test.ts` |
| **実ブラウザで測定 → 判定 → 作業が繋がる** | `scripts/e2e/core.cjs` の `hydroponicsSuite` |

e2e が実測で拾った欠陥が 1 つある: **ブラウザ版の `fetchSnapshot` に枝が無いと
台帳が空の表になる** (パス 118 の「口はあるが繋がっていない」)。台帳の組み立ては
`shared/hydroponicsControl.ts` に 1 つだけ置き、main の fetcher と web-shim の
両方が同じ関数を呼ぶ。静的スナップショットも同じ関数から作る (初回描画で空に
ならないように)。拾ったのは「台帳 8 行が届く」の検査で、**「更新が返る」の方は
最初は空の検査だった** (下の対照の記録)。

### 対照を回した記録 (2026-09-13)

13 件の対照を実際に回し、**3 件が鳴らなかった**。鳴らなかった 3 件は
「合格」ではなく、その検査についての報せなので、検査の側を直した:

| 壊した物 | 初回 | 直した後 |
| --- | --- | --- |
| 薄め量を `tank × (ec − target)` にする (反比例 → 差) | **0 件** | 2 件落ちる |
| `MG_CACO3_PER_MEQ` を 50.04 → 100 にする | **0 件** | 2 件落ちる |
| `web-shim` の `hydroponics` の枝を消す | **0 件** | 2 件落ちる |

- **薄め量**: 留めていた 1 点がリーフレタス (適正域 0.8〜1.2 → 中央 **1.0**) で、
  目標が 1 のときは反比例と差が一致する。目標が 1 でない品目 (バジル 中央 1.5 /
  ロメイン 中央 1.2) を足し、さらに**式が満たすべき関係** —— 薄めた後の EC が
  目標に一致する (溶質の量が変わらない) —— を 5 点で留めた。
- **当量重量**: 期待値を `((80 - 30) / MG_CACO3_PER_MEQ) * 1_000` と定数そのもの
  から作っていたので、定数を動かすと両辺が一緒に動いた。定数を直接固定し
  (CaCO₃ の当量重量 = 分子量 100.09 ÷ 2 価 = 50.04 mg/meq)、当量の期待値は
  手計算の 999.2006 mL で書いた。
- **ブラウザ版の枝**: `!t.includes('not_implemented')` と書いていたが、画面に
  出るのは**エラーコードではなく文面** (「ブラウザ版では live fetch を行いません。…」)
  なので、枝を消しても通った。肯定形に直した —— 取得に成功するとバッジは
  緑の「ローカル」になり、失敗すると同じ 1 枠が「エラー」に変わる。

**期待値を、検査したい定数から作ってはいけない。1 点で留めた式は、その点を通る
別の式を許す。自分が今日書いた検査も、対照を回すまで信用してはいけない。**
