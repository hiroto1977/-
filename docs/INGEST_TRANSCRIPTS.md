# 動画・音声から主張を取り込む

外部の動画 (YouTube ほか) から枠組みを取り出してシステムへ反映するときの手順と、
その正しさを機械で確かめる仕組み。

## なぜこの手順が要るのか

2026-08-27、YouTube チャンネルから抽出した枠組みで手引きを作った。そのときに:

- **組織病 3 件の語釈を名前から推測で書き、3 つとも間違っていた**
- 同じ項目を 1 日に 2 度訂正した
- 根拠が「読めないページの検索要約」だった節に、最も強い出典ラベルを付けた
  (後で降格)

原因は 1 つで、**「原文にその言い方が在る」ことを誰も確かめていなかった**。
読んだつもりで書いた文が、読んだ物のどこにも無い —— 目視では見つからない。
字面で当てれば必ず見つかる。

## 置き場所

```
ingest/<channel>/catalogue.json  既知の動画一覧 (任意)
ingest/<channel>/<videoId>.md    字幕 (frontmatter + 本文)
ingest/<channel>/claims.json     抽出した主張 (任意)
```

### 台帳 (`catalogue.json`)

字幕より先に「どの動画が在るか」だけ分かることがある。そのための一覧。

```json
{
  "channel": { "name": "…", "handle": "@…", "channelId": "UC…", "identityStrength": "confirmed" },
  "complete": false,
  "videos": [
    { "videoId": "…", "title": "…", "attribution": "owner-confirmed" }
  ]
}
```

**`attribution` は「そのチャンネルの動画だと、どうやって確かめたか」。**

| 値 | 意味 |
|---|---|
| `owner-confirmed` | リポジトリの持ち主が一覧を確認した |
| `search-only` | 検索が返しただけ。**別チャンネルの動画が混ざりうる** |

検索は別の法律事務所や別業種のチャンネルの動画も大量に混ぜて返す。
動画ページを開けない環境では、どれがどのチャンネルかを当方では判定できない。
`search-only` のまま中身を書き始めると、**別のチャンネルの主張をこの
チャンネルに帰属させる**ことになる。

**`complete` は「これで全部か」。** 検索は上位しか返さないので、既定は `false`。
この但し書きが落ちた瞬間、次の読み手は「これがチャンネルの全動画だ」と受け取る。

台帳を置くと 1 つ規則が増える —— **字幕は台帳に載っている動画のものしか
受け付けない**。載っていない videoId の字幕が現れたら、別チャンネルの動画を
混ぜたか、台帳の更新を忘れたかのどちらかである。

字幕の形:

```markdown
---
title: 動画のタイトル (逐語)
videoId: dQw4w9WgXcQ
publishedAt: 2026-07-01
---
（字幕の本文。折り返しはそのままでよい）
```

主張の形 (`claims.json`):

```json
[
  {
    "id": "cashflow-decides-insolvency",
    "videoId": "dQw4w9WgXcQ",
    "quote": "字幕から逐語で引く。1 文字も変えない",
    "claim": "そこから取り出した主張",
    "strength": "confirmed"
  }
]
```

`strength` は `src/shared/provenance.ts` の語彙 (`confirmed` / `secondary` / `gloss`)。
**定義はそこ 1 か所にしかない** —— 書き写すと `provenance.test.ts` が鳴る。

## 確かめ方

```bash
npm run ingest:check
```

見ているのは 1 つだけ ——
**主張が引く `quote` が、その動画の字幕に逐語で現れるか。**

### 何を正規化し、何を正規化しないか

| | |
|---|---|
| **吸収する** | 空白・タブ・改行・全角空白・ゼロ幅スペース |
| **吸収しない** | 文字そのもの (全角/半角、異体字、送り仮名) |

字幕は文の途中で折れるので、行の折り方の違いで落ちるなら使い物にならない。
いっぽう文字を正規化すると「だいたい合っている」を通してしまい、
**引用が引用でなくなる**。1 文字でも違えば落とす。

対照で確かめてある —— 正規化に `NFKC` を足すと、全角/半角を区別する検査が落ちる。

### `gloss` も免除しない

当方の読み解きであっても、**何を読んで解いたのか**は原文に在るはずである。
引ける物が無いなら、それは読み解きですらない。

## まだ `verify:all` の門にしていない理由

取り込み対象 (`ingest/`) が**まだ 0 件**だから。受理すべき対象が無い規則は
一度も発火せず、それは守りではなく飾りになる。同じ判断を 2026-08-29 に
`checksum-release.cjs` の `INTERMEDIATE` でしている (実測して発火 0 と分かり、消した)。

self-test は `src/shared/__tests__/ingestTranscripts.test.ts` から**実際に走る**ので、
孤児にはなっていない。字幕が入った日に門へ昇格させる。


越水はるか弁護士-守りの経営ch (`@koshimizuharuka` / `UC-KK_-m-w-Jr73bvbgQJSzQ`)。
チャンネルの同定は複数の独立した検索が一致して `confirmed`、動画一覧は検索で
集めて持ち主が確認 (`owner-confirmed`)。**字幕は 1 本も無いので、中身については
何も言えない。** タイトルから内容を書き起こすことはしない —— それは
2026-08-27 に語釈 3 件を間違えたのと同じやり方である。

## この環境から YouTube は取れない (2026-08-29 実測)

egress ポリシーが**パッケージレジストリだけ**を許しており、公開ウェブへの
経路が 1 本も無い:

| 経路 | 結果 |
|---|---|
| `curl` → youtube.com | CONNECT 403 |
| `WebFetch` → youtube.com / instagram.com / **ja.wikipedia.org** | すべて `EGRESS_BLOCKED` |
| Zapier の YouTube 連携 | アプリは在るが接続 0 件・有効 action 0 件 |

自動取得するには、環境作成時に `youtube.com` を許可した環境が要る
(`https://code.claude.com/docs/en/claude-code-on-the-web`)。
それまでは字幕を `ingest/` へ置けば、以降は同じ手順で機械が確かめる。
