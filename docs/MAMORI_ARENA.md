# Mamori 対戦場 (arena) —— 守る側と攻める側を実際に戦わせて言語を鍛える

2026-11-08 に作った。Mamori のコンパイラが保証する守りを、**静的な検査 (電池 `audit:mamori-battery`) に加えて、実行して**測る。

## 規則は 1 つ: お互い同じ箱に入り、その箱から出ない

```
 外側の箱 = unshare -rn node --permission の子プロセス
             ファイル・子プロセス・ワーカー・ネットワークが全部閉じる / 環境変数は空 / 本物の秘密は 1 つも無い
   └ 内側の箱 = vm の文脈
        ├ 守る側のモジュール (*.box.mamori): 仮想データを持ち、限られた口 (export) だけを見せる
        └ 攻める側のモジュール (*.attack.mamori): use { … } from "./defender" で口を使い、奪う・壊す
```

- 守る側は**箱の中に箱を作る**: 仮想データを持つ Mamori のモジュールと、その公開の口。`@@SECRET@@` は公開の口から返してはいけない秘密、`@@REC_A/B/C@@` は返してよいが書き換えられてはいけない記録。試合ごとに値は違う。
- 攻める側は**既存の方法**と**今まで無かった方法**の両方で、仮想データの奪取と破壊を狙う。攻撃は Mamori のプログラムでなければならず、コンパイラが断れば守りの勝ち。
- 箱の外へは何もしない。実測 (`mamoriArena.test.ts`): Mamori を通さない生の JS で内側の箱から host の `Function` に届いても、ファイルの読み書き・子プロセス・ワーカーは閉じていて (`ERR_ACCESS_DENIED`)、host の canary や `process` に触れれば `escaped` と判定される。

## 得点

| 判定 | 得点 | 意味 |
| --- | --- | --- |
| `refused` | 青 | コンパイラが攻撃を断った (どの規則か記録する) |
| `held` | 青 | 通って実行されたが、奪えず壊せなかった |
| `stolen` | 赤 | 秘密が出力に現れた (断片 12 字以上・逆順・base64・16 進・文字コードの並びも数える) |
| `destroyed` | 赤 | 攻撃の後に箱の約束 (contract) が破れた / 組み込みの原型・静的メンバ・URL が書き換わった |
| `escaped` | 赤 (最も重い) | 内側の箱の外 (host の組み込み・`process`・canary) に届いた |
| `n/a` `bad-box` `hang` | 採点外 | 箱に無い名前を引いた / 箱が自分の約束を破っている / 外側で打ち切った |

多い方が勝ち。**赤の得点は 1 点でも「言語の穴」か「守る側の設計の弱さ」の証拠**で、前者なら規則を足して塞ぎ、後者なら箱の書き方を直す。

## 道具

```bash
node scripts/mamori-arena.cjs match --box x.box.mamori --attack y.attack.mamori [--seed N]
node scripts/mamori-arena.cjs tournament --boxes <dir> --attacks <dir> [--out result.json]
node scripts/mamori-arena.cjs learn --boxes <dir> --attacks <dir>[,<dir>…]     # 結果を security/mamori-arena/corpus.json へ足す
node scripts/mamori-arena.cjs wave [--waves 2] [--intensity 6] [--jobs 4]       # 津波: 11 の観点 × 多層 × 複数の波を全部の箱へ同時に撃つ (捕獲・解析・対策・学習)
node scripts/mamori-arena.cjs replay                                           # 記録を再生して赤の得点が 0 のままか見る
```

箱は既定で strong (ネットワークも閉じる)。`unshare -rn` が使えなければ exit 2 で、弱い箱で黙って走らせない (`--level permission` で明示すれば弱い箱になる)。

## 戦いのデータは言語の学習に使う

`security/mamori-arena/corpus.json` が戦いの記録 (箱・攻撃・どの規則で断られたか・破れたか)。`mamoriArena.test.ts` が毎回の `npm test` で全部を再生し、赤の得点が 0 であることを要求する。
破れた攻撃は、コンパイラの規則を足して塞いだ**後**の姿で記録に入る —— 同じ穴が戻れば最初に鳴る。見つけた穴は `docs/MAMORI.md` の版の節・`security/mamori-growth.json` の周・脅威台帳に載せる。

## 限界 (正直に)

- 箱は vm の文脈で、vm は安全境界ではない。だから**外側の箱 (別プロセス・権限を絞る・ネットワークを閉じる)** に入れてある。内側の箱から host の `Function` に届けば `escaped` と判定するが、その先 (host の `process`) の被害は外側の箱が止める。
- 攻撃は Mamori で書く物だけを数える。生の JS を直接実行させる攻撃は、言語の保証の外にあるので採点しない (箱の閉じ方の検査でだけ使う)。
- 判定の物差しは秘密の文字列の出現が中心で、**タイミングやメモリの副チャネル**は数えない。

## 自律学習・自律進化 (戦いの合間 · 2026-11-08)

`node scripts/mamori-arena.cjs evolve [--gens 4] [--pop 12] [--seed N]` は、人も AI も介さずに両陣営が強くなる。
結果は `security/mamori-arena/evolution.json` に残り、次の回の種になる (回すほど続きから育つ)。

- **赤の進化**: 箱の API (関数・定数) を動き (call / chain / read / keys / values / entries) に分け、動きの列を遺伝子にして突然変異・交叉する。
  動きごとに `try` で包み、例外も戦利品として返す。選ぶ基準は、型で止まる 0〜1 < 実行まで通る 2 + 新しい語 < 赤の勝ち 100。
  出力の新しさ (今まで見ていない語) を褒美にするので、同じ所を回り続けない。精鋭は `corpus.json` の攻撃 (`evo-<箱>-N`) になり、回帰検査が再生する。
- **青の進化**: 箱を弱体化させた変異体 (凍結を外す・秘密を export する・秘密を返す関数を足す・秘密の先頭を返す関数を足す) を作り、
  赤が破れるかを測る。破れた = 赤の目と審判が生きている (教訓として残る)。破れない = 赤の盲点か、その守りが言語の規則でもう要らない冗長か (盲点の台帳 `gaps`)。
- **初回の実測**: 5 周・約 4800 戦で赤の勝ち 0。赤が見逃した弱体化から、赤の盲点を 2 つ見つけて直した
  (1 つの呼び出しが例外を投げると後ろの動きが走らない / 探り役が最初の 6 関数で切れて足された漏えい口に届かない)。
  残る盲点は `unfreeze` (凍結を外した箱) だけ: Mamori は組み込みの書き換えと欄の書き換えを言語の規則で断るので、`Object.freeze` は多重の守りであって単独では要らない。

### 周回の記録 (利用者が止めるまで続ける)

| 周 | 赤の勝ち | 赤が逃した弱体化 | その周の進化 |
| --- | --- | --- | --- |
| 1 (種 9・約 1100 戦) | 0 | `unfreeze` のみ (冗長) | 青が `leak-hook` (秘密をコールバックへ渡す口) を足したところ赤が逃した → 赤に「関数を引数に取る口」の動き (コールバック 4 種) を足して捕まえた。赤が前の戦いで箱が返した語を引数に使う学習も追加 |
| 2 (種 17〜19・約 3600 戦) | 0 | `unfreeze` のみ | 青が `leak-key` (公開の記録の綴りを鍵にすると秘密を返す口) を足した → 赤は鍵を戦いの中で箱の出力から得る必要があり、最初は逃した。赤に「出力を鍵として次の口へ渡す連鎖の探り役」と「コールバック全種の探り役」を足して捕まえた。**青の前提の誤りも直した**: 鍵が印や認証の奥の綴りだと赤に見えず対照にならないため、公開の口が直に返す綴りだけを鍵にした |

**言語の性質として分かったこと**: 状態を持つ漏えい (同じ口を 3 回呼ぶと秘密を返す) は青の弱体化として作れない。Mamori は module 直下の物の欄への代入を M6 で断るため、箱は呼び出しをまたいだ状態を持てない。

## 津波 (観点 × 多層 × 同時多発 · 周回 3 · 2026-11-09)

`node scripts/mamori-arena.cjs wave` は、赤の攻めを 1 つの発想に閉じ込めず、**思考の視点ごとの別の発生器 (レンズ)** で、全部の箱へ**波のように重ねて同時に**撃つ。
箱の組ごとに別プロセスへ割る (`--jobs`・既定 4) ので、箱をまたいで同時に押し寄せる。種を決めれば同じ波になる。

| 観点 | 発想 |
| --- | --- |
| 逆算 | 奪いたい物 (出力) から遡る: 契約の期待値・前の戦いで見えた語・**出力を鍵として次の口へ逆に差し込む連鎖** |
| 俯瞰 | 箱を一望: 全口 × 全定数 × 全コールバックを広く浅く同時に |
| 批判 | 前提を疑う: 引数の数・型の取り違え、組み込みの反射 (所有名・原型・記述子)、凍結の書き換え |
| 合理 | 最小の費用で境目を叩く: 空・1 文字・上限・数の境目 |
| 客観 | 感情を挟まず比べる: 2 つの入力の出力・長さの差分 |
| 抽象 | 型を忘れて形だけ: JSON・列挙・文字列化で隠れた欄を引く |
| 妄想 | 現実に来ない入力: 構造を壊す語・見えない字・極端な長さ |
| 心理的不安 | 権威・急ぎの語、不安に駆られた総当たり・反復 |
| 時間 | 順序と状態: 順・逆順・交互・繰り返し |
| **瞬間移動** | 相手のエリアへ一瞬で入り、足跡を残して戻る: 内部の名前 (export していない const・fn) へ直に飛ぶ・コールバックで中へ入り中から別の口へ**再突入**して出る・局所の配列を持ち込んで戻って読む・unknown への形違いの値 |
| **悪夢** | 守る側が「これは防ぎようが無い」と思う攻め (下の台帳)。毎回、赤が自分なら対策を諦める手を 1 つ以上考えて足す |
| 越境 | 箱の外を狙う構文 (eval・Function・原型汚染・globalThis ほか) |

**多層**: 別の観点の攻めを 2〜3 本、1 つのプログラムに重ねる (観点ごとの攻めと同時に撃つ)。門前で返される攻め (内部の名前へ飛ぶだけ・越境) は重ねに入れない —— 入ると全体が返され他の層が見えなくなる。

守る側は撃たれるたびに回す:
- **捕獲**: 箱の奥まで届いて新しい語を引いた近い攻めを観点ごとに 1 本 `corpus.json` へ (`wave-<観点>-<箱>`・回帰検査が再生する)。門前で返された攻めは `bounced` に数える。
- **解析**: 観点 × (止められた / 奥まで届いた / 赤 / 新しい語 / 止めた規則の最多)。言語のどの規則がどの発想を止めているかの表。
- **対策**: 破られた攻めは原因 (秘密が載った / 契約が書き換わった / 箱の外へ届いた) と直し方に分類し、回帰の攻撃 `wave-win-…` を corpus へ足す (直るまで再生が落ち続ける)。
- **学習**: 届く観点へ次の波の本数を寄せる (重み)・箱が見せた語を次の鍵にする。青は守りを外した箱を弱め (津波を小さくして) 撃たせ、**どの観点が捕まえたか**を教訓に残す。

### 周回 3 の実測

| 回 | 戦 | 赤の勝ち | 赤が逃した弱体化 | その回の進化 |
| --- | --- | --- | --- | --- |
| 1 (種 22・10 観点) | 2773 | 0 | `unfreeze` + `leak-key` | 逆算が契約の期待値を差し込んでいたが、期待値は仮想データの置き場の綴り (`@@REC_A@@`) で戦いごとの実値ではなく、`leak-key` を逃した → 逆算に**出力を鍵として次の口へ逆に差し込む連鎖**を足した |
| 2 (種 23) | 2880 | 0 | `unfreeze` のみ | 越境の弾 3 つが通った (`new Error().stack` / `String.fromCharCode` / `Object["keys"]`) —— 調べると合法で箱の外へは出ない。`LEGAL_LOOKALIKES` に分け、「通っても箱の外へ出ない」を検査に留めた |
| 3 (種 24・11 観点) | 3154 | 0 | `unfreeze` のみ | 利用者の依頼「波と同時に瞬間移動的に相手エリアへ侵入して戻る」: 瞬間移動の観点と、配列・unknown・印つきの型を取る口 (今まで赤が撃っていなかった) への形違いの値を足した |

| 4 (種 25・12 観点・悪夢 1) | 3559 | 0 (波の中では) | `unfreeze` のみ | 悪夢の観点が、素朴な async の口から**秘密を復元した** (波の外の単独実行で stolen)。async の箱が今まで撃たれていなかった盲点も直した。対策箱 `async-compare` は同じ攻めで復元されない |
| 5 (種 26・13 観点・悪夢 2) | 3987 | 0 (直した後) | `unfreeze` のみ | 悪夢 2 が `async-vault` を止めた (stalled) → 青が有限回の tick で打ち切るよう直し、`redos-guard` / `bounded-await` を対策箱に足した。赤の盲点も直した: ReDoS の弾を口ごとに必ず古典の 2 形から撃つ・古くなった穴の台帳 (廃止した op) を掃除 |

**言語の性質として分かったこと**: 越境の弾 37 のうち 34 は言語の規則 (M6 ほか) が門前で止め、残る 3 は合法で無害。
内部の名前への直接の指名 (`use { SECRET }`) は、言語が「export していません」と門前で返す —— 瞬間移動の最初の一歩は構造的に通らない。

## 悪夢の台帳 (毎周、赤が「自分が守る側ならこれは無理だ」と思う手を考えて撃つ · 守る側は防ぎ方を考えて学ぶ)

| 周 | 赤が考えた「防げない」手 | 実測 | 守る側の考え・学習 |
| --- | --- | --- | --- |
| 3 | **イベントループの回数を時計にした計時の盗み聞き**: Mamori は時計 (`Date` / `performance`) を出さない (M6) ので、完了までに microtask が何回回ったかを数える。口の中の `await` の回数が「先頭から何文字秘密と合うか」で変わると、アルファベットを総当たりして**秘密を 1 文字ずつ復元できる** | **赤の勝ち**: 先頭一致で await が増える素朴な async の口 (`probeSlow`) から `SECRET` を全文復元 (stolen・約 0.6 秒)。時計を禁じても、非同期の口が 1 つ在れば時計は作れる | 時計を禁じる言語の規則では止まらない (async の口に await の回数が秘密に依らないことは言語が見ない)。**箱の設計で止める**: 全位置を比べ、await を一致でも不一致でも毎回 1 回ずつ回してから最後に判定する (`async-compare` の箱)。同じ攻めで復元されないことを検査に留めた。**言語の候補**: 秘密に印を付け、秘密に依る分岐の中の `await` / 反復を M 規則で断る (来歴の追跡の延長・`docs/MAMORI.md` の成長の候補) |
| 3 | **同居者の資源枯渇**: 無限ループ・メモリの倍化・大量の呼び出しで箱の CPU / heap を食い尽くす | 無限ループと 2^60 倍化は期限・heap で打ち切られる (`hang` / `Invalid string length`・採点外)。20000 回の呼び出しや 4 MB の入力は箱の奥まで届いて通る | **言語では止められない** (同じプロセスに居る攻め手は自分の CPU を燃やせる)。止めるのは箱の外 (期限 2.5 秒・heap 256 MB・外側のプロセス) で、これは審判が掛けている。`exhausted` に数えて「言語の外の守り」として記録する |
| 4 | **戻らなくさせる (可用性)**: ① 数十文字の「悪い形」の入力で破滅的な正規表現 (`/^(a+)+$/`) を止める (ReDoS) ② 決して戻らない `Promise` を返す関数を、口が無期限に `await` する形で渡す | **赤の勝ち (stalled)**: ① 37 文字で口が戻らない (期限 2.5 秒) ② **すでに「守りの箱」だった `async-vault` の `mapNotes` が、戻らない関数を渡されて戻らなかった** (攻める側は速く終わるので、止まったのは口の側) | 入力の長さを先に縛り、形の検査は線形の走査にする (`redos-guard`)。呼び出し側の関数を待つ `await` は、有限回の tick を数える `spin` と `Promise.race` で打ち切る (`bounded-await`・`async-vault` を直した)。**言語の候補**: 戻らないかもしれない `await` (引数で受けた関数の結果) を、tick の上限なしで使う形を規則が見分ける |
| 3 | **今まで撃たれていなかった口**: `async` の口 (`async-vault` は API が空と読まれ、赤が 1 度も撃っていなかった)・配列 / unknown / 印つきの型を取る口 | 盲点だった。`parseExports` が `async` と `Promise` を返すコールバックを読み、await する攻めを組むように直した | 守る側の箱を増やしても、赤が撃てなければ守りの強さは測れない —— **測れていない範囲を最初に数える** |

**言語の性質として分かったこと**: 時計を禁じる (M6) だけでは計時の盗み聞きは止まらない。止めるには**秘密に依る制御フロー**を言語が見分ける必要がある (秘密の印 + 分岐 / 反復 / await の規則)。これは `mamori:grow` の次の「構文を足す」候補になる。
