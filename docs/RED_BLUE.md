# 攻撃側と防御側 — 守りを進化させ続ける台帳

最終更新: 2026-10-21 (ラウンド 1)

## 進め方 (1 ラウンド)

1. **攻撃側 (レッドチーム)**: 守りの実体だけを渡し、結論は渡さない。独立した監査役が、読み取り専用で破りに行く。
   報告は model の出力で、権限も正しさの保証も持たない。
2. **防御側 (私)**: 報告の各項目を**自分で再現して確かめる**。確かめられない物は「読んだだけ」のまま残す。
3. **直す**: 本物だけ。直しは「修正前のコードに当てると落ちる検査」とセットにする (対照実験)。
4. **留める**: 脅威台帳 (`security/threat-ledger.json`)・回帰検査・必要なら census・変異検査。
5. **次のラウンドの的を決める**: 直した層の隣、または今回調べていない軸。

### 直せなかった / 直さなかったこと (正直に)

- **確認の横取りは根本的には防げない**: 画面を完全に操れる攻撃者は、利用者の操作の直前に要求を出せる。値の末尾を見せることで『自分の操作か』を判別できる材料は渡したが、利用者が見ずに承認すれば通る。根本の対策は OS が保証する『ユーザー操作の証明』が要り、Electron にはない。
- **ロックアウトの悪用**: 攻撃者は利用者に断らせて (確認を出して利用者が Enter を押す) 最大 1 時間ロックさせうる。画面を乗っ取れる攻撃者は元々アプリを使えなくできるので、可用性より機密性を取った。
- **local-write は確認なし**: `teamradar/save-state`・`talent/save-state`・`stocks/unregister-ticker` は丸ごと上書き/削除できる。確認を付けると承認の疲れが増える。バックアップ (復元) が逃げ口。次のラウンドで、書く前の世代を 1 つ残す案を測る。
- **実機のダイアログは未検証**: Electron の実ダイアログ・macOS のシート・窓が最小化のとき・Windows は動かしていない (偽物で測った)。
