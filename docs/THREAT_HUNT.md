# AI による脅威の狩り (Threat Hunt) —— 手順書

> 2026-10-12 · パス 511。台帳は `security/threat-ledger.json`、機械は
> `src/shared/__tests__/threatLedger.test.ts`。

## 何をするか

人が見落とす穴を、AI の監査役 (`.claude/agents/auditor.md`) に**攻撃面ごとに独立して**探させ、
見つけた物を次の 5 段で処理する。

| 段 | やること | 残す物 |
| --- | --- | --- |
| 1. 捕縛 (狩り) | 下の 5 面の指示を、監査役 1 体ずつに並行で渡す (読み取り専用・試しの物は scratchpad) | 監査役の報告 |
| 2. 解析 | 報告の指摘を**自分で**実物のコードで再現する。再現できない物は「未確認」へ | 再現の手順と出力 |
| 3. 対策 | 本物だけを直す。直し方は最小で、守りを足す向き | 修正 |
| 4. 回帰 | **攻撃を再現する検査**を書き、修正を外すと落ちることを確かめる (対照) | 検査 (`threat: T-xxx` の印つき) |
| 5. 記録 | 台帳に 1 行 (面・型・重さ・修正・回帰検査)。確かめられなかった物は `huntBacklog` へ | `security/threat-ledger.json` |

**進化する仕組み**: 台帳の行と回帰検査は CI で双方向に突き合わされる。直した穴が黙って開き直る
(検査が消える・印が消える・行が消える) と落ちる。だから狩りを回すたびに守りは単調に増え、
同じ穴は二度開かない。攻撃の型ごとの防御表 (`classes`) は、守っている門・検査の実在を機械が確かめ、
守りの無い所を `gaps` として隠さずに書く。

## 監査役への共通の指示

- 読み取り専用。追跡ファイルは編集・commit・push しない。試しの物は scratchpad の `hunt-<面>/` へ。
- **確認した物だけ**を指摘とする: コードの道を端から端まで読み、できる限り実際に走らせる (実物の関数・
  vitest・ローカルの偽サーバ・実ブラウザ)。届く道の無い物は「未確認 / 強化案」へ分ける。重さを盛らない。
- 既に `docs/SECURITY.md` / `docs/SECURITY_AUDIT.md` / この台帳に在る物は、直しが不完全だと示せない限り数えない。
- 返す物: ① 確認した指摘 (重さ・題・file:line・攻撃者と前提・手順・走らせた再現と出力・最小の直し)
  ② 未確認 / 強化案 ③ 確かめて健全だった物 (覆った範囲が分かるように)。

## 攻撃面 (台帳の `surfaces` と一致させる)

## surface: main-ipc

Electron の主プロセスと preload。脅威: レンダラーが乗っ取られた (XSS) 状態から `window.serviceHub` を通して
OS・ファイル・他サービスの資格情報へ届く / 第三者の応答や利用者の URL が主プロセスの出口へ届く。
見る所: `main.ts` の IPC ハンドラ・窓の生成と遷移・権限、preload、`secrets.ts`、`oauth.ts`、`atomicWrite.ts`、
`shellOpenGate.ts`、`clients/*.ts` の書き出し、`eraseAll`、`clients/index.ts` の振り分け。
問い: 書き出し先の外へ書けるか (symlink・`..`・絶対パス・Windows の装置名・`:`) / 実行形式を開かせられるか /
他のサービスの資格情報を読めるか / 型の取り違え・prototype の鍵で関門を越えるか / 自分の読み口が断る物を書かせられるか。

## surface: renderer

レンダラーとブラウザ版 (`dist/standalone.html`)。脅威: 第三者の内容・取り込むファイル (バックアップ・CSV)・
同じ origin の頁・保存領域の写しを持つ者。見る所: XSS の出口・Markdown の描画・出荷される CSP・`sw.js`・
BroadcastChannel / storage の受け口・`security/vault.ts` ほかの暗号・バックアップの復元・ライブラリのプレビュー・CSV。
問い: 攻撃者の文で `javascript:` のリンクやスクリプトが走るか / 取り込んだバックアップで KDF の回数や鍵を
弱められるか / IV の再利用 / 細工した記録で画面を壊し、消す操作に届かなくできるか。

## surface: network

外向きの通信と資格情報。脅威: 悪意ある・乗っ取られた API や プロキシの応答 (転送・巨大な本文・型違い) /
利用者に保存させた URL / 利用者が置いた Worker を呼べる攻撃者。見る所: `httpLimits.ts`・`proxy.ts` と
`docs/PROXY_EXAMPLE.md` の Worker・`privateTarget.ts`・`shared/api/*.ts` と `main/clients/*.ts` の URL の組み立て・
`shared/ai/*`・`oauth.ts` / `pkce.ts`・Ollama・webhook。
問い: 資格情報が持ち主以外のホストへ渡るか (転送・`#`・利用者情報・バックスラッシュ・似た文字) /
SSRF の遮断表が漏らす形 / Worker が開いた proxy になるか / 本文が上限の前にメモリを使い切るか。

## surface: ai

AI / LLM の経路。脅威: **間接プロンプトインジェクション** (メールの件名・Issue・Slack・Notion・予定・
取り込むファイル・利用者が設定した互換 API の応答) で ① 確認なしの書き込み ② 情報の持ち出し ③ アプリの声の
なりすまし ④ AI の画面の持続的な破壊 を起こさせる。見る所: `voiceCommand.ts` と `voiceWriteRequirements.ts`・
コンシェルジュ・AI アシスタント・`assistantMarkdown.ts`・ベスト3・advisor 各種・`skills.ts`・`web-shim.ts` の AI の経路。
問い: モデルや第三者の文から、利用者が送る中身を見て確認しないまま書き込みに届く道は在るか / 確認の見せ方を
欺けるか (双方向制御・長文・改行・似た名前) / 送り先を名乗らずに外へ送っていないか。

## surface: supply-chain

供給網・CI/CD・開発の道具。脅威: fork からの PR / 乗っ取られた npm・Action・MCP サーバ / 読み切れない大きな差分を
混ぜてマージさせる。見る所: `.github/workflows/*`・`dependabot.yml`・`package.json` と lockfile・`.claude/settings.json`・
`scripts/*.cjs` (PR の中身を読む門)・整合性チェーン・`inline-html.cjs`。
問い: fork の PR が秘密や書き込み権限の token を得られるか / 特権のある実行が後で読む物 (cache・成果物・script の道) を
PR が汚せるか / 門そのものに素通りの道があるか (種類・置き場所・symlink・大きさ・符号化)。

## 回す頻度

- **攻撃面を変える PR を出す前**: その面だけを狩る。
- **定期**: 下の「輪を回す仕組み」が週 1 で 1 面ずつ回す (5 面は 5 週で 1 巡)。月 1 回を目安に 5 面すべてを人が回す
  のは今までどおりでよい。**実行のたびに利用料が掛かる** —— 予約を止めるのは利用者の判断で、止めれば毎日の
  報告が「止まった」と Issue に出す。
- 台帳の `huntBacklog` に残った物は、次の狩りの最初に渡す (`hunt:cycle -- brief` がその面の分を並べる)。

## 輪を回す仕組み (探索 → 解析 → 対策 → 報告) —— 2026-10-28 · T-214

姿勢の測定 (下の節) は「次はどこを狩るか」を決めるが、**狩りそのものを起動する側は人だった**。利用者の指示
「探索→解析→対策→報告を繰り返す仕組みを仕込んで」で、起動と記録も機械にした。

| 段 | 誰が | 何で |
| --- | --- | --- |
| 起動 | Claude Code の予約 (週 1 · 新しいセッション) | 指示文は `docs/HUNT_CYCLE_PROMPT.md` と同じ物 |
| 探索 | 予約されたセッション → 監査役 | `npm run hunt:cycle -- brief` が**次の面を決定的に決め** (姿勢が止まったと言う面 → 最後に狩った日が最も古い面)、その面の手順書の節・狩り残し・再確認の期限・薄い型・記録の雛形を 1 枚にする |
| 解析・対策 | 同じセッション | 上の 5 段 (捕縛 → 解析 → 対策 → 回帰 → 記録) と同じ。直しは **draft PR**。マージはしない |
| 報告 | 同じセッション | PR の本文 + `npm run hunt:cycle -- record <json>` で 1 周を `security/hunt-cycles.json` へ。**4 段すべてが揃わないと記録できない** (解析・対策の穴は脅威台帳に実在する id、報告は PR 番号か出さなかった理由) |
| 監視 | 毎日の `dependency-audit` | `hunt:cycle -- status` と同じ測定を報告に載せ、最後の周から **14 日** (cadence 7 日 × 2) 止まれば要対応として常設 Issue に出す |

- 自動なのは **検知・順位づけ・起動・解析・対策の提案 (draft PR)・記録** まで。マージは人が決める (供給網の攻撃面を
  自分で広げないため)。
- 費用: 1 周 = 1 セッション分の利用料。止めるときは予約を無効にする (リポジトリ側は何も変えなくてよい —— 止まったことは
  Issue が言う)。
- 機械: `src/shared/__tests__/huntCycle.test.ts` (面の選び方・記録の検め・止まった判定・毎日の報告への配線・指示文と
  道具の一致)。輪の台帳と脅威台帳は `record` が突き合わせる。

## 輪を回し続ける側 (姿勢の測定)

`npm run audit:security-posture` (毎日の `dependency-audit` も同じ測定を報告に載せる) が、台帳から
**次の一手**を決定的に導く。網にも AI にも触れないので費用は掛からない。

| 出す物 | 意味 |
| --- | --- |
| 面ごとの速度 | 見つけた数・直近 30 日・最後に見つけた日・狩り残し・緩和のみの数 |
| **止まった面** | 狩り残しが在るのに 21 日以上、新しい穴が出ていない → 次の狩りの最初に渡す |
| **再確認の期限** | 「確かめて健全だった」から 45 日 → 守りが後の変更で崩れていないか測り直す |
| 守りの薄い型 | 型ごとの 守りの数 − 穴の数 が小さい順 |
| 次に狩る候補 | 面の収穫 (直近 90 日の重み付き) + 狩り残しの古さ。日付の無い物は古さ 0 (順位を盛らない) |

止まった面・期限切れ・読めない台帳は毎日の報告で要対応に数えられ、常設 Issue に出る。姿勢の測定が自動なのは検知と
順位づけまでで、**起動は上の「輪を回す仕組み」の予約が担う** (2026-10-28 まで人が回していた)。
収穫は台帳の歴史が浅い間 (2026-10-12 開始) は件数にほぼ等しい。

## 正直な限界

- これは「最強」を約束しない。約束するのは、**見つけた穴は記録され、再現する検査で塞がれ続け、守りの無い型は
  `gaps` として表に出る**ことだけである。
- 監査役も見落とす。報告が途中で切れることもある (2026-10-12 の供給網の監査は分類器に止められ、詳細を失った ——
  `huntBacklog` に残した)。
- 端末・アカウント・ネットワークへの侵入はこのリポジトリから見えない (`docs/SECURITY.md` の「正直に言う」)。
