# ローカルAI評議会（council）

複数のローカルLLMが役割を分担し、常に話し合いながら提案をまとめる常駐デーモンです。
`start-all.sh`（および `--watch` の60秒監視ループ）から自動起動され、落ちても再起動されます。`stop-all.sh` で停止します。

## 役割とモデル（LiteLLM `127.0.0.1:4000` 経由）
| 役割 | 既定モデル | 環境変数 |
|---|---|---|
| 提案者 | qwen3-1.7b | COUNCIL_PROPOSER |
| 批判者 | glm-edge-1.5b | COUNCIL_CRITIC |
| 検証者 | internlm2.5-1.8b | COUNCIL_VERIFIER |
| 議長（まとめ役） | balanced（Qwen2.5 3B） | COUNCIL_CHAIR |

追加モデルは llama-swap が1つずつ読み込むため、同時に常駐するのは1モデルだけです。失敗したら `fast` に自動で切り替えます。

## 流れ
1. 議題を選ぶ（優先順）：村のチャットで清継さんが評議会に送った発言 → `inbox.md` → 停止中のサービス → リポジトリの `docs/REMAINING_WORK.md` → 環境の改善点
2. 提案者 → 批判者 → 検証者 を `COUNCIL_TURNS` 周（既定2、空きメモリが少ないと1周）
3. 議長が「決定」と「次のアクション」を書き、`decisions.md` に追記
4. `COUNCIL_INTERVAL` 秒（既定600秒）待って次へ。清継さんの発言が届くとすぐ始めます

## 議題の追加
- 村のページ下のチャットで「評議会全体へ」を選んで送信（最優先）
- または `inbox.md` に `- 議題` の形で1行追加（処理済みは `- [済]` になります）

## 3Dの村（http://127.0.0.1:8091）
Three.js（`web/vendor` に同梱、ビルド不要）のボクセル風の村です。評議員とローカルサービスがそれぞれ家を持ち、発言中の役は中央テーブルへ歩いて吹き出しを出します。停止中のサービスは灰色で寝ています。議長の決定は掲示板に貼られ、空の色は東京時間で昼夜が変わります。ドラッグで視点を回せます。

`web/vendor/three.module.min.js` は Three.js r160 のビルド済みファイルです。先頭のライセンス表記は Copyright 2010-2023 Three.js Authors、SPDX-License-Identifier: MIT です。`OrbitControls.js` は同じ版の examples 由来です（MIT。このファイル自体にはライセンスヘッダがありません）。minify 済みの `three.module.min.js` は eslint の対象外です。

- キャラをクリックして送信すると、その役のモデルが役柄のまま清継さんに返事します
- 会話は `user_thread.md` に、議論は `logs/YYYY-MM-DD.md` に保存されます
- 状態は `/api/state`（JSON）

## 安全のための制限
- できることは、このディレクトリへのファイル書き込みと読み取り専用の確認だけです。git push や外部への送信はしません
- サーバーは 127.0.0.1 だけで待ち受け、POST はループバックかつ同一オリジンの JSON のみ受け付けます（4KB以下、本文500字まで）
- 画面上の文字はすべて textContent で表示し、HTMLとしては解釈しません
- 空きメモリが `COUNCIL_MIN_FREE_MB`（既定1500MB）未満なら回を飛ばし、1回の呼び出しは `COUNCIL_TIMEOUT` 秒（既定240）で打ち切ります
- 小さいモデルなので、内容は参考程度です（事実の誤りや中国語の混入があります）
